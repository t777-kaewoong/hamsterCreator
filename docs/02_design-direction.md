## 1. 제품 정의

### 한 문장

> **햄스터S 말판·트랙을 화면에서 배치하고, A4/B4/A3로 나눠 인쇄할 수 있는 PDF와 정답 코드를 함께 뽑아주는 교사용 웹 도구.**

### 하는 것

- 격자 말판 설계 (셀에 아트 타일 배치, 선 그리기, 아이콘·라벨 배치)
- 임의 크기 맵을 A4/B4/A3로 자동 분할 + 재단선·정렬 마크·조립 안내도
- 정확한 축척의 인쇄용 PDF 생성 (mm 좌표 직접 지정)
- 출발→도착 경로 자동 탐색 → `board_forward()` 정답 코드 생성
- 인쇄·센서 캘리브레이션 시트 제공, 센서 오작동 위험 사전 경고

### 하지 않는 것 (명시적 제외)

- 수업 지도안·활동지 텍스트 생성
- AI 모델 학습 도구 (Ⅱ단원용)
- 햄스터 실물 제어·연결 (엔트리/파이썬이 담당)
- 학생 계정·과제 제출·협업 (교사 단독 사용)
- 범용 벡터 그래픽 편집 (격자와 8mm 선이라는 제약 안에서만)

## 2. 핵심 설계 원칙

**원칙 1 — 맵은 이미지가 아니라 데이터다.**
모든 산출물(PDF, 정답 코드, 축소도, 변형본)은 하나의 JSON 문서에서 파생된다. 이미지를 직접 편집하는 경로는 만들지 않는다.

**원칙 2 — 물리 규격을 앱이 지킨다.**
피치 50mm, 선폭 8mm는 사용자가 실수로 깨뜨릴 수 없어야 한다. 변경은 가능하되 명시적 경고를 동반한다.

**원칙 3 — 인쇄는 PDF로 한다.**
`window.print()`를 쓰지 않는다. mm 좌표를 직접 찍은 PDF를 생성하고, 모든 시트에 축척 검증 눈금을 넣는다.

**원칙 4 — 이음매는 절대 선을 가로지르지 않는다.**
시트 경계는 항상 셀 경계(선 중심에서 25mm)에 놓는다. 종이 단차·그림자가 바닥 센서를 속이는 것을 구조적으로 차단한다.

**원칙 5 — 경고는 하되 막지 않는다.**
센서 위험·규격 이탈은 표시만 한다. 최종 판단은 교사가 한다.

## 3. 데이터 모델

### 3.1 좌표계

```
원점 = 맵 좌상단 (0, 0), 단위 = mm, x→오른쪽, y→아래
셀 (c, r)  :  c = 0..cols-1,  r = 0..rows-1
셀 영역    :  (c·50, r·50) ~ (c·50+50, r·50+50)
격자 노드  :  셀 중심 = (c·50+25, r·50+25)     ← 로봇이 서는 지점
```

> **왜 셀 중심이 노드인가**
> `playbot_A4.pdf` 실측: 셀 x 23.52~73.62mm, 수직선 x 44.57~52.57mm.
> 선 중심 48.57 = 셀 시작 23.52 + 25.05 → **선은 셀 정중앙을 지난다.**
> 즉 아트 타일 한 칸 = 로봇이 서는 한 지점이고, `board_forward()` 1회 = 50mm 이동이다.

### 3.2 격자 = 노드·엣지 그래프

`move_on_board.pdf` p1/p3을 보면 격자선이 **전부 있는 게 아니라 일부만** 있습니다. 빠진 구간이 곧 벽이고, 남은 구간이 로봇이 다닐 수 있는 길입니다.

따라서 격자를 **완성된 격자무늬**가 아니라 **켜고 끌 수 있는 엣지의 집합**으로 모델링합니다.

```
노드 (c,r)  —  수평 엣지 h[c][r] : (c,r) ↔ (c+1,r)
            —  수직 엣지 v[c][r] : (c,r) ↔ (c,r+1)
```

**이 한 가지 결정으로 따라오는 것들:**

| 얻는 것 | 방법 |
|---|---|
| 미로 설계 | 엣지 켜기/끄기 |
| 정답 경로 | 그래프 BFS 최단경로 |
| 정답 코드 | 경로 + 방향 전환 → `board_forward()`/`board_left()`/`board_right()` |
| 도달 불가 검증 | 연결 요소 검사 → "도착 지점에 갈 수 없습니다" 경고 |
| 난이도 지표 | 경로 길이, 회전 횟수, 분기 수 |
| 난이도 변형 | 시드 기반 엣지 재생성 |

### 3.3 문서 스키마 (초안)

```jsonc
{
  "schema": "hamsterS-map/1",
  "meta": { "title": "미로 탈출 1모둠", "unit": "Ⅰ-3-1", "note": "", "modified": "..." },

  "board": { "cols": 10, "rows": 8, "pitch": 50, "lineWidth": 8 },

  // 배경 아트 — 셀에 스냅, row-major 배열
  "cells": [ { "art": "dungeon/stone_a", "rot": 0, "flip": false }, null, ... ],

  // 격자선 — 존재하는 엣지만 기록
  "edges": { "h": [[0,3],[1,3], ...], "v": [[4,0],[4,1], ...] },

  // 경계 진입로 (맵 밖으로 나가는 반칸 선)
  "stubs": [ { "node": [0,3], "dir": "W" } ],

  // 자유곡선 트랙 (라인트레이서 / 자율주행) — v1.5
  "strokes": [ { "points": [[x,y],...], "width": 8, "closed": false } ],

  // 자유 배치 오브젝트 (아이콘, 장애물 표시 등)
  "props": [ { "asset": "icon/fire", "x": 125, "y": 75, "w": 40, "h": 40, "rot": 0 } ],

  // 텍스트 라벨
  "labels": [ { "text": "출발", "x": 25, "y": 25, "rot": 0, "size": 8,
                "color": "#fff", "onLine": true } ],

  "markers": { "start": { "cell": [0,3], "heading": "E" },
               "goals": [ { "cell": [9,0], "name": "도착" } ] },

  "print": { "sheet": "A4", "orientation": "landscape",
             "seam": "butt", "overlap": 0 }
}
```

**`cells`(격자 스냅)와 `props`(자유 배치)를 나눈 이유:** 공식 자료가 그렇게 만들어져 있습니다. 아트 타일은 50mm 격자에 정확히 스냅되어 있고, 햄스터 아이콘·라벨은 자유 위치입니다.

### 3.4 렌더 순서 (공식 자료와 동일하게)

```
① 흰 배경
② cells  — 50×50mm 아트 타일
③ strokes — 자유곡선 8mm 검정
④ edges  — 격자선 8mm 검정          ← 아트 위에 덮어 그림
⑤ props  — 아이콘
⑥ labels — 텍스트                    ← 선 위 흰 글씨 가능 (board_game.pdf의 "+2/-3")
⑦ markers — 출발/도착 표시
```

## 4. 편집기 설계 ★핵심

> "핵심 기능은 오브젝트 배치 등을 사용자가 쉽게 조작해서 자료를 제작하는 것" — 이 절이 그 요구에 대한 답입니다.

### 4.1 화면 구성

```

├────────┬────────────────────────────────────────┬────────────┤
│ 팔레트 │                                        │  속성      │
│        │            캔버스                      │            │

│ ▸얼음  │       ┌──┬──┬──┬──┐                    │  크기      │

```

### 4.2 도구 세트

| 단축키 | 도구 | 동작 |
|---|---|---|
| `V` | 선택 | props/labels 선택·이동·회전·삭제. 다중 선택 |
| `L` | **선 긋기** | 격자 위를 드래그 → 지나간 엣지 ON / `Alt`+드래그 → OFF |
| `B` | **타일 브러시** | 팔레트에서 고른 타일을 클릭·드래그로 연속 배치 |
| `R` | 영역 채우기 | 사각 드래그 → 한 번에 채움 |
| `I` | 스포이드 | 캔버스의 기존 타일을 브러시로 집기 |
| `E` | 지우개 | 셀 아트 / 엣지 / 프롭 지우기 |
| `T` | 텍스트 | 라벨 추가 (선 위 흰 글씨 모드 포함) |
| `M` | 마커 | 출발·도착 지정, 출발 방향 설정 |

공통: `Ctrl+Z`/`Ctrl+Shift+Z` 실행취소·재실행, `Ctrl+C/V` 복사·붙여넣기, `Space`+드래그 화면 이동, 휠 확대/축소.

### 4.3 오브젝트 배치 인터랙션

**배치 방법 3가지를 모두 제공합니다** — 사람마다 손에 붙는 방식이 다릅니다.

1. **스탬프 모드 (가장 빠름)**
   팔레트에서 타일 클릭 → 커서가 그 타일이 됨 → 캔버스를 클릭하거나 드래그해서 연속 배치. 도장 찍듯이.
2. **드래그 앤 드롭**
   팔레트에서 캔버스로 끌어놓기. 처음 쓰는 사람에게 직관적.
3. **마지막 타일 재사용**
   우클릭 = 직전에 쓴 타일 즉시 배치.

**배치 중 조작**

| 키 | 동작 |
|---|---|
| `R` | 90° 회전 |
| `F` | 좌우 반전 |
| `Shift` 드래그 | 격자 스냅 해제 (자유 배치) |
| `Alt` + 영역 채우기 | **같은 테마 안에서 랜덤 변형**으로 채움 → 배경이 단조롭지 않게 |

**`Alt` 랜덤 채우기**는 실제 시간을 많이 아껴줍니다. 던전 배경 80칸을 채울 때 돌바닥 4종이 자연스럽게 섞이는 걸 클릭 한 번으로 처리합니다.

**보조 장치**

- **레이어 잠금** — 배경 타일을 잠그고 프롭만 만지기 (반대도 가능)
- **프리셋** — "A4 기본 말판 5×4", "부록 재난구조", "부록 배리어프리", "빈 격자" 등 원클릭 시작
- **정렬 보조** — 프롭 이동 시 인접 셀·선 중심에 스냅 가이드 표시
- **미니맵** — 큰 맵 작업 시 전체 위치 파악

### 4.4 에셋 팔레트

**내장 아트 타일 — 6테마 36종** (`custom_objects.pdf`에서 추출, 50×50mm / 433px)

## 5. 출력 파이프라인

### 5.1 용지별 격자 수용량 (실측 규칙으로 계산 — 공식 A4/A3 레이아웃과 일치 확인)

| 용지 | 방향 | 페이지 | **격자** | 활동 면적 | 여백(좌우/상하) |
|---|---|---|---|---|---|
| **A4** | 가로 | 297×210 | **5×4 = 20칸** | 250×200mm | 23.5 / 5.0mm |
| A4 | 세로 | 210×297 | 4×5 = 20칸 | 200×250mm | 5.0 / 23.5mm |
| **B4** | 가로 | 364×257 | **7×5 = 35칸** | 350×250mm | 7.0 / 3.5mm |
| B4 | 세로 | 257×364 | 5×7 = 35칸 | 250×350mm | 3.5 / 7.0mm |
| **A3** | 가로 | 420×297 | **8×5 = 40칸** | 400×250mm | 10.0 / 23.5mm |
| A3 | 세로 | 297×420 | 5×8 = 40칸 | 250×400mm | 23.5 / 10.0mm |

> B4는 JIS 규격(257×364mm) 기준입니다. 학교 복사기 표준입니다.
> **B4 한 장(35칸)이 A4 두 장(40칸)에 근접합니다.** 이음매 없이 만들 수 있으므로, B4가 되는 상황이면 B4 단일장을 우선 제안하도록 합니다.

### 5.2 타일링 시 총 격자

| 구성 | 격자 | 실제 크기 |
|---|---|---|
| A4 가로 2×2장 | **10×8 = 80칸** | 500×400mm |
| A4 가로 3×2장 | 15×8 = 120칸 | 750×400mm |
| A4 가로 3×3장 | 15×12 = 180칸 | 750×600mm |
| B4 가로 2×2장 | 14×10 = 140칸 | 700×500mm |
| A3 가로 2×2장 | 16×10 = 160칸 | 800×500mm |

**기본 시나리오는 "A4 4장 → 10×8칸 / 500×400mm"**로 잡습니다. 책상 두 개 붙인 넓이에 맞고, 미로로서 충분한 복잡도가 나옵니다.

### 5.3 타일링 규칙

```
맵 크기        = cols·50 × rows·50 (mm)
시트 활동면적  = floor(W/50)·50 × floor(H/50)·50
시트 분할      = 셀 단위로만 자름 → 이음매는 항상 셀 경계
                 = 선 중심에서 25mm 떨어진 지점 (원칙 4)
```

**각 시트에 인쇄되는 것**

| 요소 | 목적 |
|---|---|
| 활동 면적 (격자 + 아트) | 본체 |
| 재단선 (점선) + 모서리 재단 마크 | 정확한 자르기 |
| 정렬 삼각 마크 (변 중앙) | 이웃 시트와 맞추기 |
| 시트 번호 `1-2` + 이웃 방향 표시 `← 1-1 / 1-3 →` | 조립 순서 |
| **50mm 검증 눈금자** | 인쇄 배율 확인 (원칙 3) |
| `※ 실제 크기(100%)로 인쇄하세요` 문구 | 배율 사고 예방 |

**이음매 방식 2가지**
- `butt` (맞대기, 기본) — 재단 후 뒷면에 테이프. 두께 단차 없음
- `overlap 5mm` (겹치기) — 풀칠. 단차 발생하나 조립이 쉬움 → 이 경우 겹침부가 선을 덮지 않는지 자동 검사

**별도 1장: 조립 안내도** — 전체 맵 축소도 + 시트 번호 배치 + 자르기/붙이기 순서.

### 5.4 함께 나오는 산출물

| 산출물 | 내용 |
|---|---|
| **정답지** | 최단 경로 도해 + 파이썬 코드 (`board_forward()` 시퀀스) + 이동 칸 수 / 회전 횟수 |
| **조립 안내도** | 시트 배치도 |
| **캘리브레이션 시트** | §6.1 |
| (옵션) 축소 도해 | 학생 배부용 A4 1장 축소본 |
| (옵션) 테이프 배치 도면 | 좌표표 — 절연테이프로 만들 때 |

## 6. 검증 기능

### 6.1 캘리브레이션 시트 (A4 1장, 학기 초 1회)

```
[1] 선폭 사다리   5 / 6 / 7 / 8 / 9 / 10mm 검은 선
      → 우리 반 햄스터가 안정적으로 읽는 최소 선폭 확인
[2] 명도 계단     흰색 → 회색 10단계 → 검정
      → 이 프린터·이 용지에서 센서가 "선"으로 오인하는 명도 임계값
[3] 50mm 기준자
      → 인쇄 배율 검증
[4] 센서 간격 측정 눈금
      → 바닥 센서 2개의 좌우 간격 실측 (01번 문서 §4.1 미확정 항목)
```

측정값은 앱에 저장되어 이후 모든 디자인 검증의 기준이 됩니다.

## 7. 기술 스택

| 영역 | 선택 | 근거 |
|---|---|---|
| 빌드 | **Vite + TypeScript** | 정적 산출물, 설치 불필요 |
| UI | **React** | 도구 상태·선택·실행취소 등 상태가 복잡. 순수 DOM으로 가면 유지보수 비용 증가 |
| 상태 | Zustand + 명령 스택 | 실행취소/재실행 구현 단순화 |
| 캔버스 | **Canvas 2D** | 360셀 × 이미지 규모에서 SVG는 DOM 폭증. 오프스크린 캐싱 적용 |
| **PDF** | **pdf-lib + @pdf-lib/fontkit** | mm 좌표 직접 지정, PNG 임베드, 한글 폰트 서브셋 임베드 가능 |
| 저장 | IndexedDB + `.hsmap.json` 입출력 | §9 리스크 참조 |
| 에셋 | 사전 추출 PNG 36종 + 자체 SVG 아이콘 | 런타임 PDF 파싱 불필요 |

### 배포 형태 — 2가지를 함께 제공

- **(A) 정적 호스팅 + PWA** (권장) — 첫 접속 후 오프라인 동작, IndexedDB 저장 정상
- **(B) 단일 HTML 파일** (`vite-plugin-singlefile`) — 학교 PC가 외부망 차단·설치 불가일 때. USB로 옮겨 더블클릭

> **(B)의 제약:** `file://`에서는 크롬이 IndexedDB/localStorage를 막습니다.
> → **(B) 모드는 자동 저장 없이, 파일 내보내기/불러오기만으로 동작**하도록 설계합니다.
> 앱이 실행 환경을 감지해 저장 UI를 바꿉니다. 이건 나중에 붙이기 어려우므로 처음부터 반영합니다.
