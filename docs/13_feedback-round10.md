# 13. 사용자 후기 10차 — 마우스 크기 조절·타일 팔레트 공간 (2026-10-29)

> 순서: 원인 분석 → 해결 방향·명세 → 검증. docs/12 다음 회차입니다.

## 1. 후기와 원인

| 후기 | 원인(코드 확인) |
|---|---|
| 크기는 항상 마우스로 조절하고 싶음 | 칸 타일(cells)은 선택해도 크기 핸들이 없었음(`handlesFor`가 칸에 빈 목록). 그림(props)만 핸들이 있어서, 칸 타일은 "칸에서 떼기"를 먼저 해야 했음 |
| "같은 테마 섞어 칠하기" 표현이 어색함 | 팔레트에서는 "테마"라는 말을 안 쓰고 "종류"라고 부름. 무슨 동작인지(무작위로 섞임)도 드러나지 않음 |
| 타일 배치 패널이 너무 좁아져 쓰기 불편함 | ① 아래 고정 영역이 놓는 자리·크기(칸)·체크 2줄·조작법 5줄로 약 330px를 차지해, 타일 그리드는 한 줄 남짓만 보였음. ② 그리드가 77px 고정 3열이라 세로 스크롤 막대가 생기면 폭이 모자라 셋째 열이 잘리고 가로 스크롤 막대까지 생김 |

## 2. 해결 방향·명세

### 2.1 마우스 크기 조절
- 칸 타일을 선택하면 그림과 같은 **크기 핸들 8개**(모서리 4 + 변 4)가 보임.
- 핸들을 끌기 시작하면 같은 자리·같은 크기의 그림으로 떼어 낸 문서를 기준으로 크기를 바꿈(`selectionEdit.detachCellToProp`). 실제로 끌기 전에는 문서를 바꾸지 않아, 핸들을 눌렀다 떼기만 하면 칸 타일 그대로.
- 끌기 한 번 = 실행취소 한 칸(되돌리면 원래 칸 타일). 모서리는 기본 비율 유지(그림과 같음).
- 팔레트의 "크기(칸)" 줄(docs/12 §2.2)은 뺌 — 놓은 뒤 마우스로 바꾸는 쪽으로 일원화하고 그 자리를 그리드에 돌려줌. 정확한 칸 크기가 필요하면 인스펙터 "크기(칸)" 단추(그대로 둠).

### 2.2 타일 팔레트 공간
- 아래 고정 영역을 3줄로: **놓는 자리 / 선 아래에 깔기 / 랜덤으로 칠하기** + 접힌 "조작법 보기"(누르면 펼침, 기본 접힘). 조작법에 "선택(V) — 놓은 타일 모서리를 끌어 크기 조절" 추가.
- 그리드는 남은 폭을 3열로 똑같이 나눔(`repeat(3, minmax(0, 1fr))`, 타일 정사각형). 가로로 넘치지 않음.
- 1080px 미만(팔레트 240px)에서는 체크 칸 옆 보조 설명을 숨겨 한 줄 유지(설명은 마우스를 올리면 툴팁).
- 첫 사용 말풍선은 좁으면 두 줄로 접힘(가로로 잘리지 않게).

### 2.3 문구
- "같은 테마 섞어 칠하기" → **"랜덤으로 칠하기"** + 옆 설명 "같은 종류 타일을 섞어요".

## 3. 검증 (2026-10-29)

- `npx tsc -b` 0건, `npm run build` 성공, 크기 변경 회귀 31항목 통과.
- 개발 서버 1280×760: 타일 그리드가 약 4줄 보이고 가로 스크롤 없음. 보물상자를 칸에 놓고 선택 → 핸들 8개 표시 → 오른쪽 아래 핸들을 끌어 그림 100×100으로 바뀌고 선택도 그 그림으로 옮겨감. 실행취소 한 번에 칸 타일로 복귀. 콘솔 오류 0건.
- 1024×700(팔레트 240px): 타일 한 변 59px, 가로 넘침 없음(scrollWidth = clientWidth), 체크 줄 한 줄 유지.
