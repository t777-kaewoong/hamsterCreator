# 10. 사용자 후기 7차 — 종이 이음매 진입로·도착 햄스터 방향 (2026-10-27)

> 순서: 원인 분석 → 해결 방향·명세 → 검증. docs/09 다음 회차입니다.

## 1. 후기와 원인

| # | 후기 | 원인(코드 확인) |
|---|---|---|
| 1 | 종이와 맞닿는 부분에 진입로 추가가 안 됨 | 진입로는 **맵 바깥**을 클릭할 때만 생김(gridMath `stubAtPoint`). 종이 사이 이음매 위를 누르면 격자선 토막 전체가 켜지고 꺼질 뿐. 종이별 "진입로 넣기"도 맵 바깥 테두리에만 넣음. 맵 안쪽 진입로는 지우개로도 못 지웠음 |
| 2 | 도착지를 놓을 때 햄스터 방향 설정이 안 됨 | 도착 마커에 방향 데이터가 없고, 햄스터 도착은 늘 위를 보게 그려졌음 |

## 2. 해결 방향·명세

### 2.1 이음매 진입로 (1)
- 격자선 도구로 **종이 이음매를 건너는 토막**을 누르면 누른 쪽 **절반**만 켜고 끔. 절반 = 그 종이 쪽 격자점에서 이음매까지의 반 칸 선(진입로, 데이터는 기존 `Stub`). 양쪽 절반이 다 켜지면 온전한 격자선 하나로 합침. 이음매가 아닌 토막은 지금처럼 전체 토글. Alt는 지우기(`sheetLines.setSeamHalf`).
- 격자선 팔레트 "종이별로 한꺼번에 → 진입로 넣기"는 고른 종이의 **네 변 모두**(이웃 종이와 맞닿는 변 포함)에 넣음. 이음매를 건너는 격자선이 이미 있으면 그 자리는 건너뜀.
- 지우개: 맵 안쪽 진입로도 그 반 칸 선 가까이(선 굵기 절반 + 4mm)를 누르면 지움.
- 진입로는 정답 계산에 쓰지 않으므로 정답 코드·검증은 바뀌지 않음.

### 2.2 도착 햄스터 방향 (2)
- `GoalMarker.heading?`(없으면 위). 팔레트에서 도착지 + 햄스터 모양일 때 **"도착 방향"** 4방향 선택이 나타나고, 놓는 도착지가 그 방향을 봄. 인스펙터(도착지 선택)에도 햄스터일 때 "방향" 줄.
- 기본 모양(과녁)은 방향 표시가 없어 선택지를 숨김.

## 3. 검증 (2026-10-27)

- `npx tsc -b` 0건, `npm run build`·`build:single` 성공, 크기 변경 회귀 31항목 통과.
- 개발 서버 A4 2장(이음매 x=250mm), 합성 클릭(화면 1px = 1mm로 환산 확인):
  - 이음매 토막 h(4,1)의 왼쪽 절반(240,75) → 진입로 (4,1)→E. 오른쪽 절반(262,75) → 진입로 대신 격자선 h(4,1) 하나. 왼쪽 절반 다시 → 격자선 없어지고 오른쪽 진입로 (5,1)→W만 남음. 보통 토막(100,75) → 격자선 h(1,1) 전체 토글.
  - 지우개로 (262,75) → 안쪽 진입로 (5,1)→W 지워짐.
  - 종이 1-1 "진입로 넣기" → 18개(위 5·아래 5·왼쪽 4·이음매 쪽 오른쪽 4).
  - 도착지 + 햄스터 → 팔레트 "도착 방향" 표시, 왼쪽 선택 후 놓은 도착지 `heading: 'W'`. 인스펙터에 "도착 방향" 줄.
- 한계: 도착 햄스터가 실제로 돌아간 모습은 출발 햄스터와 같은 그리기 함수라 화면 캡처로는 따로 확인하지 못함.
