# 햄스터S 수업도구 웹앱 — 문제 상황 분석

작성일: 2026-09-05
작성 근거: `말판/` 폴더 PDF 23종 실측, 교과서 PDF(192p) 전문, 「프로그래밍과 인공지능 로봇」 과목 교육과정(hwp) 전문

---

## 0. 이 문서의 성격

"말판 만들기가 번거롭다"는 체감 문제를, **측정 가능한 사실**로 분해한 문서입니다.
개발 방향 설계(다음 단계)의 입력값이 되도록 다음 세 가지를 분리해서 정리했습니다.

1. 지금 가진 자산이 실제로 어떤 규격인가 (§1) — 추측 아님, 전부 PDF에서 좌표 추출
2. 번거로움의 원인이 정확히 무엇인가 (§2)
3. 그래서 무엇을 만들어야 하는가에 대한 제 의견 (§5)

### 1.2 교과서 부록(pp.180~191)의 맵 자산

교과서는 부록에 **인쇄해서 쓰는 활동 맵 12장**을 넣어 두었습니다. 유형이 위와 또 다릅니다.

| 부록 페이지 | 활동 | 맵 형태 |
|---|---|---|
| p180 | Ⅰ-5 장애물 피해 이동 (60쪽) | 격자 + 장애물 아이콘 |
| p181 | Ⅰ-5 원 테두리 따라가기 (66쪽) | 대형 원 |
| p182 | Ⅱ-2 신호등 이미지 (104쪽) | 학습데이터용 이미지 카드 |
| p183~185 | Ⅲ-1 재난 구조 | 격자 + 아이콘(불/밸브/사람) + 원형 구역 + 진입로 |
| p186~187 | Ⅲ-2 쓰레기 분리수거 | 수거함 **입체 전개도(풀칠·접는선 포함)** |
| p188~189 | Ⅲ-3 자율주행 | **비격자 자유곡선 도로** + 신호등 카드 |
| p190 | Ⅲ-4 배리어 프리 | 격자 + 방 이름 라벨(거실/현관/화장실) |
| p191 | 라인 트레이서 | 자유곡선 |

**여기서 나오는 결정적 사실 두 가지:**

1. 부록 맵은 **교과서 판형(210×270mm)에 맞춰 축소**되어 있습니다. p185의 검은 선 실측 폭은 **3.6mm**로, 표준 8mm의 45% 수준입니다. → 부록을 그대로 A4에 인쇄하면 햄스터 바닥 센서 기준에서 규격 미달입니다. 확대 복사가 전제된 자료입니다.
2. 부록에는 **입체 소품 전개도(p187)**가 포함됩니다. 근접 센서 활동은 평면 인쇄물만으로 안 되고, 센서가 감지할 높이를 가진 물체가 필요합니다. 이건 "말판" 문제와 별개의 준비 부담입니다.

### 1.3 자산 구조에서 확인된 렌더링 규칙

`move_on_board.pdf`를 z-order까지 뜯어보면 제작 규칙이 명확합니다.

```
① 흰 배경 → ② 50×50mm 아트 타일(비트맵) → ③ 8mm 검은 격자선(벡터, 최상단) → ④ 라벨 텍스트
```

즉 **검은 선은 항상 아트 위에 덮어 그린다**는 규칙입니다. 이건 앱이 그대로 따라야 할 렌더 순서입니다.

## 2. 문제 상황 분해

체감 문제("선 긋고 이미지 붙이는 게 번거롭다")를 원인별로 쪼개면 7개입니다. **P1~P3이 진짜 병목**이고, P4~P7은 그 결과로 생기는 2차 비용입니다.

---

### P1. 출력 물리 한계 — "학교 프린터는 A4다"

| 항목 | 내용 |
|---|---|
| **현상** | 쓸 만한 크기의 말판을 한 번에 인쇄할 수 없다 |
| **증거** | 제공된 완성 말판의 최대 크기가 A2(88칸). 그런데 A2/A3은 **단일 페이지 PDF**라서 A4 프린터로는 출력 불가 |
| **원인** | 셀 50mm × 선폭 8mm라는 규격상, 의미 있는 미로(예: 10×8칸)는 최소 500×400mm를 요구. A4 활동면적은 250×200mm뿐 |
| **정량화** | 1000×700mm 말판을 A4로 만들려면 → **A4 16장, 재단 32회, 이음매 24곳** |
| **영향** | 여기가 "번거로움"의 실체. 디자인이 아니라 **재단·정렬·접합 노동** |

**추가 실측 — 타일링은 원리상 가능합니다.**
A4 말판은 좌우 여백 23.5mm를 잘라내면 첫 선 중심에서 25.0mm(=반 칸) 지점이 단면이 됩니다. 두 장을 맞대면 피치가 정확히 50mm로 이어집니다. 즉 **"정확히 재단하면 이어붙일 수 있는데, 정확히 재단하는 게 사람 손으로는 고통"**인 상태입니다. → 앱이 재단선·겹침 여백·정렬 마크를 찍어주면 해결 가능한 문제.

---

### P2. 아날로그 조립 노동 — "잘라서 풀칠한다"

| 항목 | 내용 |
|---|---|
| **현상** | 테마 말판을 만들려면 `custom_objects.pdf` 6장을 인쇄 → 50mm 타일 120개를 가위로 오림 → 빈 격자판에 붙임 |
| **증거** | `custom_objects.pdf`의 존재 자체가 "오려 붙이는 워크플로"를 전제. 교과서 p143도 *"검은색 절연 테이프나 종이, 굵은 펜 등을 활용한다"*고 안내 |
| **원인** | 배치가 **디지털에서 결정되지 않고 물리 세계에서 결정**됨 |
| **영향** | 배치를 바꾸려면 다시 오리고 붙여야 함 → **수정 비용이 제작 비용과 같음**. 재사용 불가 |

---

### P3. 재사용 불가능성 — "한 번 만들면 그 배치로 고정"

| 항목 | 내용 |
|---|---|
| **현상** | 반마다 난이도를 바꾸거나, 모둠마다 다른 미로를 주고 싶어도 못 함 |
| **원인** | 완성물이 **평면 이미지(PDF)**라서, 배치 정보가 데이터로 남지 않음 |
| **영향** | ① 학급별 차별화 포기 ② 정답 유출(옆 모둠과 같은 맵) ③ 내년에 다시 처음부터 |
| **교육과정 충돌** | 교육과정 「평가의 방향 (다)」 *"학급 내에서 개인차를 고려한다"*, 「교수·학습 (나)」 *"학습자 간 개인차를 고려하여 문제를 제시하며 점진적으로 심화"* — 맵이 고정되면 이 요구를 물리적으로 못 지킴 |

### P4. 정답·활동지의 수작업 동반 생성

말판 하나를 만들면 따라오는 것들:
- 출발→도착 최단 경로 (`board_forward()` / `board_left()` / `board_right()` 시퀀스)
- 모둠별 다른 미션 카드
- 채점 기준 (몇 칸 만에 도착했는가)

**현재는 이걸 교사가 눈으로 세어서 손으로 씁니다.** 맵이 6개면 6번 반복. 맵 제작보다 이쪽이 더 오래 걸릴 수 있습니다.

---

### P5. 센서 오작동을 유발하는 디자인을 사전에 못 걸러냄

햄스터S 바닥 센서는 적외선 반사식입니다. **"검게 보이는 것"이 아니라 "적외선을 덜 반사하는 것"**을 선으로 인식합니다. 그런데:

- 제공된 아트 타일 중 **초콜릿 타일(짙은 갈색)**, **돌 타일(중간 회색)** 등은 명도가 낮음
- 교사가 임의 이미지를 넣으면 어두운 사진이 그대로 들어감
- 코팅지·광택지는 정반사로 오히려 센서를 속임
- 이어붙인 테이프 자국이 그림자를 만들어 선으로 읽힘

**현재는 "인쇄해서 돌려봐야" 압니다.** 수업 직전에 발견하면 대안이 없습니다.

---

### P6. 인쇄 배율 오차 — 조용히 규격이 깨짐

브라우저·프린터의 기본값은 대부분 "페이지에 맞춤(Fit to page)"입니다.
- A4 문서를 A4에 "맞춤" 인쇄 → 여백 처리 때문에 보통 **94~97%로 축소**
- 선폭 8mm → **7.5~7.7mm**, 셀 피치 50mm → **47~48.5mm**

**한 장짜리면 티가 안 나지만, 여러 장을 이어붙이면 누적 오차로 격자가 어긋납니다.** 그리고 `board_forward()`는 격자 간격을 전제로 동작하므로, 피치가 틀어지면 로봇이 칸을 놓칩니다. 원인 파악이 가장 어려운 유형의 실패입니다.

---

### P7. 자산 유형이 8가지인데 제작 방법이 제각각

§1.1의 A~H는 서로 다른 도구·다른 규칙으로 만들어져 있습니다. 격자 말판을 만드는 노하우가 라인트레이서 트랙에 재사용되지 않고, 룰렛에도 재사용되지 않습니다. 교사 입장에서는 **활동 종류마다 새로 배워야 하는** 상태입니다.

### 여기서 도출되는 것

**(1) 격자 말판이 전체의 60% 이상**이지만, **자유곡선 트랙 없이는 Ⅰ-5-3과 Ⅲ-3을 못 합니다.** 두 모드 모두 필요합니다.

**(2) "격자 + 자유곡선"이 한 맵에 섞이는 경우가 실재합니다.** 부록 p185(재난 구조)가 격자 + 원형 구역 + 직선 진입로 혼합입니다. 모드를 완전히 분리하면 이 맵을 못 만듭니다.

**(3) 교과서가 학생에게 "디자이너" 역할을 명시적으로 배정합니다.**
> 교과서 p143 — 모둠의 역할: *"디자이너: 프로젝트를 위한 지도를 디자인하고 제작"*

그리고 [9프인03-01]은 *"해결 가능한 문제를 탐색하고 문제 해결을 위한 아이디어 구상"*을 요구합니다.
→ **이 앱은 교사 준비 도구인 동시에 학생 활동 도구가 될 수 있습니다.** 이건 부가 기능이 아니라 성취기준에 직접 걸리는 용도입니다.

| 아트 타일 | 50×50mm, 433×433px(≈220dpi) | `custom_objects.pdf` |
| 로봇 크기 | 35×40×30mm | 사용자 제공 사양 |
| 근접 센서 | 좌·우 2개, 1~30cm | 사용자 제공 사양 |
| 바닥 센서 | 좌·우 2개, 적외선 반사식 | 사용자 제공 사양 |

**미확정:** 바닥 센서 2개의 좌우 간격. 이 값이 "선 주변 몇 mm까지 어두운 색을 금지할지"를 결정하는데, 문서로 확인이 안 됩니다. → **실측 필요** (또는 앱이 캘리브레이션 시트로 교사가 직접 재게 함).

### 4.2 인쇄 환경

- 대부분의 학교: **A4 흑백 다수 + A3 소수 + 컬러는 제한적**
- 인쇄실에 대형 플로터가 있는 학교도 있음 → A0/A1 단일 시트 출력 옵션도 가치 있음
- **컬러 인쇄 비용**은 실질적 제약. 테마 아트를 풀컬러로 20칸 인쇄 = 학급 수 × 모둠 수만큼 비용 발생

### 4.3 학교 PC 환경

- 설치 프로그램 반입이 어려운 경우가 많음 → **설치 없는 웹앱이 맞는 선택**
- 다만 외부망 차단·구버전 브라우저 가능성 → **서버 없이, 오프라인에서도 도는 정적 웹앱**이 안전
- 파일 저장은 로컬(다운로드/업로드) 기반이 현실적

### 4.4 저작권 ⚠️

`말판/` 폴더의 아트 타일 36종은 (주)로보메이션 배포 자료에서 나온 것으로 보입니다.
- **교사가 수업에 쓰는 것**과 **앱에 번들해서 배포하는 것**은 법적 지위가 다릅니다.
- 앱에 기본 내장하면 재배포가 됩니다.

→ 이건 PRD 전에 정리하고 가는 게 좋습니다. §5 O7에 제안을 적었습니다.

## 5. 제 의견 — 개발 방향 제언

의견이 있습니다. 8가지입니다. **O1~O3은 이걸 안 지키면 앱을 만들어도 문제가 안 풀린다**고 보는 것들입니다.

---

### O1. 「그림 편집기」가 아니라 「맵 데이터 편집기」로 만들어야 합니다 ★가장 중요

지금 하시는 작업이 힘든 이유는 **결과물이 이미지라서**입니다. 이미지는 사람만 읽을 수 있으므로, 정답·변형·검증을 전부 사람이 해야 합니다.

맵을 **JSON 데이터**(격자 크기 / 셀별 속성 / 벽·장애물 / 출발·도착 / 라벨 / 아트 참조)로 정의하면, 같은 데이터에서 다음이 **전부 자동으로** 나옵니다.

| 산출물 | 자동 생성 근거 |
|---|---|
| 인쇄용 PDF | 데이터 → 렌더 |
| **정답 코드** (`board_forward()` 시퀀스) | 데이터 → 최단경로 탐색(BFS) |
| 화면 시뮬레이터 | 데이터 → 로봇 이동 재생 |
| 모둠별 난이도 변형 | 시드 바꿔 재생성 |
| 학생 활동지 | 데이터 → 축소판 + 빈칸 |
| 채점 기준(최소 이동 수) | 경로 길이 |

**이미지 편집기로 만들면 이 표의 첫 줄 하나만 나옵니다.** 이게 이번 프로젝트의 성패를 가르는 단일 결정이라고 봅니다.

---

### O2. 1순위 기능은 「예쁘게 그리기」가 아니라 「A4로 쪼개기」입니다

§2 P1에서 계량한 대로, 실제 노동은 재단·정렬·접합입니다. 그래서 v1의 킬러 기능은:

- 임의 크기 맵 → **A4/A3 자동 분할**
- 각 장에 **재단선 + 정렬 마크 + 겹침 여백(풀칠 영역) + 시트 번호(1-1, 1-2…)**
- **조립 안내도 1장** (전체 축소도 + 배치 번호)
- 이음매가 **셀 경계(선 중심에서 25mm)** 에 오도록 자동 배치 → 이어붙인 자리가 선을 가로지르지 않게

이게 되면 "A2 말판이 필요한데 A3 프린터밖에 없다"는 상황이 그냥 해결됩니다.

---

### O3. 브라우저 인쇄(`window.print()`)를 쓰면 안 됩니다 — PDF를 직접 생성해야 합니다

§2 P6 문제 때문입니다. HTML을 브라우저로 인쇄하면 배율이 조용히 깨지고, 브라우저·프린터마다 다르게 깨집니다.

**해결:** `pdf-lib` / `jsPDF` 같은 라이브러리로 **mm 좌표를 직접 지정한 PDF를 클라이언트에서 생성**하고, 인쇄 대화상자에서 **"실제 크기 / 100% / 배율 없음"**을 선택하도록 안내 문구를 PDF 여백에 인쇄합니다.

그리고 **모든 시트에 검증용 눈금**을 넣습니다: 여백에 "↔ 50mm" 자 표시. 인쇄 후 자로 재서 50mm가 아니면 배율이 틀린 겁니다. 30초 만에 확인 가능.

---

### O4. 캘리브레이션 시트를 넣으면 좋겠습니다 (P5 + P6 동시 해결)

A4 한 장에 이런 걸 담습니다.

```
[1] 선폭 사다리: 5 / 6 / 7 / 8 / 9 / 10mm 검은 선을 나란히
    → 우리 반 햄스터가 몇 mm부터 안정적으로 읽는지 확인
[2] 명도 계단: 흰색 → 회색 10단계 → 검정
    → 이 프린터·이 용지에서 센서가 "선"으로 오인하는 명도 임계값 확인
[3] 50mm 기준자
    → 인쇄 배율 검증
[4] 센서 간격 측정 눈금
    → 바닥 센서 2개 간격 실측 (§4.1 미확정 항목)
```

교사가 학기 초에 **한 번** 인쇄해서 재보면, 이후 앱은 그 값을 저장해 두고 디자인을 자동 검증합니다.
"12장 인쇄해서 붙였는데 로봇이 선을 못 읽는" 사고를 앞단에서 막습니다. 제가 보기에 이게 다른 도구에 없는 차별점입니다.

---

### O5. 센서 안전성 자동 검증을 넣습니다

O1의 데이터 모델 + O4의 임계값이 있으면 자동으로 경고를 띄울 수 있습니다.

- 선 주변 안전 영역(폭 = 센서 간격 기반)에 **임계 명도 이하 픽셀**이 있으면 경고
- 배경 아트가 전체적으로 어두우면 경고
- 선 간격이 로봇 폭(40mm)보다 좁으면 경고
- 이음매가 선 위를 지나가면 경고

경고는 **차단이 아니라 표시**로 합니다. 선생님이 판단하실 일이지, 앱이 막을 일은 아닙니다.

---

### O6. 「대형 인쇄」 말고 저비용 대안 두 가지를 같이 지원하는 게 실용적입니다

컬러 대형 인쇄는 매번 하기엔 비용이 큽니다. 데이터가 있으면 다음도 그냥 나옵니다.

**(a) 테이프 배치 도면**
A4 흑백 1장에 "검은 절연 테이프를 어디에 몇 cm 붙일지" 좌표표를 출력.
→ 화이트보드나 전지 위에 테이프로 1m급 말판을 만들 수 있고, **반복 사용·즉시 수정** 가능. 재료비 거의 0.

**(b) 50mm 모듈 타일 카드**
50×50mm 타일을 낱장으로 인쇄 → 코팅 → 매 수업 재배치.
→ **한 번 만들면 배치는 무한히 바뀝니다.** 앱은 "이번 맵에 필요한 타일 목록 + 배치도"만 출력.
→ P3(재사용 불가)의 근본 해법이고, 학생이 직접 맵을 설계하는 활동(교과서 p143 디자이너 역할)에도 그대로 쓸 수 있습니다.

개인적으로 **(b)가 장기적으로 가장 남는 투자**라고 봅니다.

---

### O7. 아트 자산은 「번들」이 아니라 「사용자가 불러오기」로 가는 게 안전합니다 ⚠️

§4.4 문제입니다. 제안:

- 앱 기본 내장 = **직접 그린 도형/아이콘 + 공개 라이선스(CC0) 자산**만
- 로보메이션 자산 = **사용자가 자기 PC의 PDF/PNG를 불러오는 경로** 제공
  (앱이 `custom_objects.pdf`를 열어 50mm 타일 36개를 자동 추출 → 로컬 저장)
- 이러면 앱을 다른 선생님께 공유해도 저작권 문제가 안 생기고, 각자 자기 자료를 불러 쓰면 됩니다

기술적으로도 어렵지 않습니다. 이번에 제가 실제로 추출해 봤고, 타일이 정확히 50mm 격자로 배치돼 있어 자동 추출이 잘 됩니다.

### O8. v1 범위를 좁히자는 제안

§1.1의 A~H 8종을 다 만들면 v1이 안 끝납니다. 우선순위 제안:

## 7. 한 줄 요약
